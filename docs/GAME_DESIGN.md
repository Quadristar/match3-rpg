# GAME_DESIGN.md(3マッチパズル＋RPG)

このゲーム固有の設計ドキュメント。
共通基盤(シーン管理・アセット・レイアウト・セーブなど)の設計は `docs/ARCHITECTURE.md` を参照。
設計を変更した場合は、このファイルと `docs/decisions/` を更新すること。

---

## 1. 目標

- ブラウザ上で PC・スマートフォンから遊べる、見た目と演出の品質が高い 2D パズルRPG
- キャラクターの大量のアニメーション素材に頼らず、**高品質な立ち絵＋背景＋UI＋パズル演出＋エフェクト＋カメラ演出＋サウンド**で完成度を出す

### 基本のゲームループ

```
タイトル → ステージ選択 → バトル開始 → パズル操作 → パネル消去
→ 結果に応じて攻撃・スキル → 敵にダメージ → 撃破 → 経験値・報酬
→ キャラクター成長 → 次のステージ
```

## 3. パズルシステム

### 方式: 先に全部計算して、後から再生する

1回の入れ替えに対し、ロジック側が**連鎖の最後まで**を一気に計算して結果を返す。

```ts
type MoveResult = {
  valid: boolean;
  move: Move;                // 入れ替えた2マス(a, b)
  reason?: InvalidMoveReason; // valid: false のときの理由(盤面の外・隣でない・揃わない)
  steps: CascadeStep[];      // 連鎖1段ごと
  finalBoard: BoardState;
  reshuffled?: BoardState;   // 詰み発生時の再配置結果
};

type CascadeStep = {
  matches: MatchGroup[];     // 種類・形状(3/4/5/L/T)・セル
  removed: Cell[];
  falls: { from: Cell; to: Cell }[];
  spawns: { cell: Cell; tile: Tile }[];
};
```

描画側(BoardView)は `steps` を順番に再生するだけにする。
正確な型は `src/systems/puzzle/types.ts`(実際は `valid` で分かれる型。上は概要)。

この方式の利点:

- 演出(ヒットストップ・スロー・カメラ)を追加してもロジックが壊れない
- 演出スキップ・倍速の実装が容易
- `resolveMove(board, a, b, rng)` の戻り値を検証するだけでテストできる
- 同じシードなら同じ結果になり、不具合を再現できる

### 最低限の機能

パネル生成 / 配置 / 入れ替え / 3個以上のマッチ判定 / 消去 / 落下 / 補充 / 連鎖 / コンボ数 / 入力制御 / 詰み検出と再配置 / パズル終了判定

- 初期盤面は揃っていない状態で生成する
- 揃わない入れ替えは元に戻す

### 拡張への備え

- パネルは `Tile = { kind: TileKind; modifiers: TileModifier[] }` のデータとして扱う
- 特殊パネル(爆発など)は「消去時に追加で消すセルを返すルール」として追加する
- マッチ判定は形状も返す(特殊パネルの生成条件に使う)
- 将来の候補: 特殊パネル、属性パネル、スキルゲージ、コンボ倍率、連鎖ボーナス、制限時間、ステージ固有ギミック

### 入力

- 「ドラッグ」と「2回タップ」の両方で入れ替えを受け付ける(`docs/decisions/001-puzzle-swap-input.md`)
  - ドラッグ: 指を置いたパネルから、パネル幅の 40%(仮仕様・設定値)動いた時点で方向を確定し、指を離す前に入れ替える
  - 2回タップ: 1回目で選択(枠を表示)、隣をタップで入れ替え、隣でないパネルをタップで選択し直し
- 入力は `swap(a, b)` という操作の意図に変換してからロジックに渡す(`BoardInputController`)
- 連鎖の演出中は入力を受け付けない

### 表示と再生(Phase 3b)

- `MoveResult` を、Pixi に依存しない「再生の手順」(`playbackPlan`)に変換し、`BoardView` が GSAP のタイムラインで順に再生する
  - 手順: 入れ替え → 消去(連鎖の段数付き) → 落下と補充(補充は盤面の上から落ちる) → 段の間の待ち → … → 再配置
  - 揃わない入れ替えは、入れ替えてから元に戻す
- 各段階の時間と全体の速さ(`playbackSpeed`)は `boardViewConfig.ts` の設定値。倍速・スキップは全体の速さ(タイムラインの timeScale)の1か所で変える
- 画面が回転したら、再生を即座に終え、再生後の盤面から描き直す
- パネルの表示物は ObjectPool で再利用する
- `?seed=数値` で盤面の乱数のシードを固定できる(不具合の再現用)。`?debug` のときはシードを画面に表示する

## 4. バトルシステム

```
MoveResult ─▶ AttackResolver ─▶ Action[] ─▶ BattleState.apply() ─▶ BattleEvent[]
              (data/tileEffects を参照)                          (演出キューへ)
```

- **AttackResolver**: 消えたパネルを行動に変換する。変換規則は `data/tileEffects` に置く
  - 「パネル色＝属性＝その属性のキャラが攻撃」型にも、「パネル種類＝行動の種類(攻撃・回復・防御・MP)」型にも、データの差し替えで対応できるようにする
- **DamageCalculator**: 純粋関数。攻撃力・防御・属性倍率・コンボ倍率を入力とし、バフ・デバフは修飾子のリストとして差し込める形にする
- **TurnFlow**: 状態機械
  `入力待ち → パズル解決 → 味方行動 → 勝敗判定 → 敵行動 → 勝敗判定 → 入力待ち`
- 時間制限を導入する場合は「ターン終了条件」の一つとして追加する

### Phase 4a で決めたこと(仮仕様)

- 有効な入れ替え1回を1ターンとする。揃わない入れ替え・再配置はターンを消費しない
- 味方の攻撃は1ターンに1回(同じ効果のパネルを1つの攻撃にまとめる)。行動するのは編成の先頭
- ダメージ: 連鎖の段ごとに「消えたパネル数 × 攻撃力 × 段の倍率(1 + 0.25 × (段 − 1))」を合計し、防御を引く。小数は切り捨て、最低 1
- バフ・デバフは修飾子(合計への倍率 → 防御への倍率 → 最終の倍率の順)として差し込む
- 敵は「次の攻撃までの残りターン数」を持ち、毎ターン 1 減らして 0 で攻撃し、間隔の値に戻す
- 味方の攻撃で敵の HP が 0 になったら、敵は行動せずに勝利。敵の攻撃で味方が全員 HP 0 になったら敗北
- `BattleEvent` の種類: `turnStart` / `partyAttack`(段ごとの内訳・HP の前後) / `enemyAttack`(HP の前後) / `enemyCountdown` / `victory`(経験値) / `defeat`
- **BattleDirector**(`app/`): PuzzleSystem の結果を BattleSystem に渡し、`BattleEvent[]` を演出キューとして presentation に流す

将来の候補: パーティ、属性、スキル、必殺技、状態異常、バフ・デバフ、装備、アイテム

## 5. データ設計

- キャラクター・敵・スキル・ステージ・パネル効果などは TypeScript のデータファイル(`satisfies` で型検査)で管理する
- 新しいキャラクターや敵を、データの追加だけで増やせることを目指す
- データ同士はIDで参照し、整合性はテストで検査する
- 画像・音声はデータ内で**アセットキーのみ**を持つ

## 6. キャラクター表現

- 基本は立ち絵。走る・殴るなどのフレームアニメーションは前提にしない
- 登場・フェード・拡大縮小・左右移動・揺れ・フラッシュ・発光・表情差分・カットイン・エフェクト・UI演出で表現する

## 9. 最初のプロトタイプ仕様(すべて仮仕様)

- 盤面 7×7、パネル5種(種類A〜E)
- 隣接パネルの入れ替え。揃わなければ元に戻す
- 3個以上で消去 → 落下 → 補充 → 連鎖。連鎖段数をコンボ数とする
- 全種類が攻撃になる: 1パネルあたり 10 × (その段の倍率)。段の倍率は 1 + 0.25 × (段 − 1)(1段目 1.0、2段目 1.25 …)。1ターンの合計から防御を引く
- 敵1体(HP 300)。3ターンごとに味方へ20ダメージ
- 味方 HP 100、Lv1
- 勝利で EXP +50 → リザルト → 規定値でレベルアップ → タイトルへ
- 敗北でリザルト(敗北)
- 見た目は図形と文字のみ、音なし
